# Implementation

Read the project rules and plan the change. Add tests and make a local commit with a clear message. Use `push`, remote branches, and PRs only if explicitly authorized in the task. Keep `runtime` outside the project.

Use [`project-verification`](../project-verification/SKILL.md). Update the docs with `technical-writing`. After successful verification run `task submit <id> --file submission.json` with summary, SHA in `commit`, docs, and run ID. Fix findings and resubmit a verified snapshot. Report budget or access blockers to the Lead.
